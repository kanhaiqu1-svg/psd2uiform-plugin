# 图片与 prefab 复用

`ref ` 和 `refp ` 是设计师明确声明的资源链接。它们决定使用哪份资源，不决定 UI 类型。普通导入使用图层标签；AI 模式由模型识别类型、角色、组成和父子关系。

## 命名

| 图层名称 | 含义 |
| --- | --- |
| `Gold Coin.img` | 普通图片，导出为 `Gold Coin.png` |
| `ref Gold Coin.img` | 复用共享目录中的 `Gold Coin` 图片，或 PSD 中唯一同名素材 |
| `ref Icons/Gold Coin.png.img` | 精确引用共享图片目录中的 `Icons/Gold Coin.png` |
| `refp Cards/Item.prefab` | 精确引用共享 prefab 目录中的 `Cards/Item.prefab` |

图片目录与 prefab 目录分别使用 Unity 配置中的 `SharedAssetsOutput` 和 `SharedPrefabOutput`。PS 工具中设置对应的磁盘目录。选择器保留完整相对路径和扩展名，图片与 prefab 分别过滤。

引用可以不写扩展名，但同目录同时存在 `Icon.png` 和 `Icon.jpg` 时必须指定扩展名。插件不会任意选择其中之一。引用不允许绝对路径或 `..` 上级路径。

普通图片导出移除已识别的 UI 标签，保留合法名称中的大小写、中文、空格和标点；非法文件名字符替换为下划线，Windows 保留名自动处理。仅重名时添加数字后缀，并避开已有合法名称。例如 `Icon`、`Icon`、`Icon_1` 输出 `Icon.png`、`Icon_2.png`、`Icon_1.png`。名称已以 `.png` 结尾时不重复添加扩展名。

## 图片解析顺序

1. 优先使用共享目录中精确匹配的现有图片。需要绑定 Image 时，仅在必要时改为 Sprite 导入；保留文件像素和已有九宫格边框，不自动裁剪复用图片。
2. 没有现有图片时，使用原始 PSD 中唯一的同名非引用图层导出一份共享 PNG。同名源不唯一时报告歧义，需调整命名。
3. 如果 PSD 中全部实例都带同一个 `ref` 标记，使用原始 PSD 顺序中的首个声明导出一份共享 PNG，其他实例引用它。

显式指定 JPG、TGA 等扩展名表示引用已有文件；文件缺失时报告该绑定失败，不另造 PNG 代替。显式 `.png` 或不写扩展名允许从 PSD 创建共享 PNG。

多个实例保留各自的 UI 节点、位置、尺寸和素材 ID，共享同一个图片资产。不会根据图片相似度自动合并实例。原始同名非引用图层在被 `ref` 使用时也使用共享输出，不另存一张图片。

## AI 和嵌套

AI 输入的 `reuse` 列携带原始 `ref/refp` 声明。引用组作为一个完整素材展示，不再把组内图层作为独立素材供模型重复使用。引用素材必须独占对应的图像元素或 prefab 实例，不能与其他素材烘焙合并。

AI 生成节点单独保存引用信息，模型给节点起名、重复应用、保存重载均不会改变链接。再次识别仍从原始 PSD 建立快照。

`refp` 使用 Unity prefab 实例。常规模式在本地 prefab 缺失时仍可从标记的原始子树导出共享 prefab；AI 模式不凭图片捏造其内部结构，缺失 prefab 记录为局部问题。其他有效控件与独立子元素继续生成。

UI 嵌套遵从声明的树。ScrollView 下的 Item、图片及 prefab 实例在生成时进入其 `Content`；Dropdown 模板内部的 ScrollView 同样使用真实的 `Content`。结构挂接保留子元素位置、尺寸及嵌套层级。

## 局部失败

缺失、歧义、导入失败只影响对应资源绑定。AI 类型不会被本地改成 Image/Text，其他正确节点继续应用和生成。生成问题保存在 `Library/PSD2UIForm/generation-reports/<prefab GUID>.json`。已有历史输出不自动删除。
